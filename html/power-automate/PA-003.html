PA-003 Be clear and descriptive so reviewers can quickly understand what initiates

Trigger names should be clear and descriptive so reviewers can quickly understand what initiates the flow.

Use a verb-noun format for trigger names.
Include key details such as the data store and triggering event.
Avoid abbreviations and prefer full words for clarity.
Clear and descriptive trigger names make it easier to understand what initiates the flow.
Well-named triggers serve as documentation for team members and stakeholders.
Descriptive names simplify troubleshooting by providing immediate context.
Examples
Do
When a new item is created
When a new item is created
Value: When a new item is created Clearly describes the event in plain language.
Do
When a new contact is added to Dataverse
When a new contact is added to Dataverse
Value: When a new contact is added to Dataverse Includes both the event and the data source.
Do
When a file is created in SharePoint
When a file is created in SharePoint
Value: When a file is created in SharePoint Uses full words and identifies the source system.
Don't
File Created SP
File Created SP
Value: File Created SP Abbreviated and unclear.
Don't
Manually trigger a flow
Manually trigger a flow
Value: Manually trigger a flow Default name that does not describe the business purpose.
Don't
Recurrence
Recurrence
Value: Recurrence Default name with no indication of what the schedule is for.
