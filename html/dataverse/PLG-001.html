Power Platform Best Practices
Plugins / dataverse
PLG-001 Use a namespace-based naming convention that describes the plugin's purpose.

Plugin class names must use a namespace-based naming convention that describes the plugin's purpose. Do not hardcode table schema names, pipeline stages, or event names into the class name, since a single plugin class can be registered on multiple tables and stages, and its configuration may change over time. Follow this pattern: ` [AppName].Plugins.[TableName (if table-specific)].[Action/Purpose] `

AppName: The name of the application or solution (e.g., CRM, Sales, FieldService).
Plugins: A fixed namespace segment indicating the plugin layer.
TableName *(optional)*: Include the table name as a namespace segment only when the plugin is specific to a single table.
Action/Purpose: A descriptive class name that explains what the plugin does.
Namespace-based naming keeps plugin classes organized and discoverable in large solutions with many plugins.
Avoiding table schema names and pipeline stages in the class name allows the same plugin to be registered on multiple tables, events, or stages without the name becoming misleading.
Plugin registration details (table, stage, event) are configured in the Plugin Registration Tool and can change independently of the code. The class name should describe *what* the plugin does, not *where* it is registered.
Examples
Do
CRM.Plugins.Accounts.ValidateEmail - a plugin under the CRM app namespace
CRM.Plugins.Accounts.ValidateEmail - a plugin under the CRM app namespace
CRM.Plugins.Accounts.ValidateEmail - a plugin under the CRM app namespace, specific to the Accounts table.
Do
CRM.Plugins.Contacts.SendWelcomeNotification - specific to the Contacts table.
CRM.Plugins.Contacts.SendWelcomeNotification - specific to the Contacts table.
CRM.Plugins.Contacts.SendWelcomeNotification - specific to the Contacts table.

Sales.Plugins.Orders.PreventActiveDeletion - under the Sales app namespace
Sales.Plugins.Orders.PreventActiveDeletion - under the Sales app namespace, specific to Orders.
